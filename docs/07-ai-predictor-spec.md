# 07 — AI Overload Predictor

## Goal
Forecast, per tenant and for the host, the probability that **within the next H seconds (H=10)** some resource saturates or victims' p99 exceeds `k×baseline`. Give detector/throttle **lead time**.

## Contract (sidecar, Python FastAPI)
`POST /predict` ← `{ts, tenants:[{id, features:[...]}], host:{...}}` → `{p_overload_host, tenants:[{id, p_overload, top_factor, eta_s}], model:"baseline|gbm"}`.
Also `GET /health`, `POST /model/select`.

## Features (per tenant, windows of 1s; lags 1..30)
rate, cost-units/s, queue depth, queue-wait p95, exec p95, cpu share, mem share, db conns, bytes/s, rejections/s, plus first/second differences (slope, acceleration), and host utilization.

## Baseline (mandatory)
- Holt (double exponential smoothing) forecast of cost-units/s and queue depth → project to H seconds → compare against capacity.
- z-score of current vs rolling mean/std for anomaly flag.
- `p_overload` = logistic of (projected_load/capacity − 1) combined with anomaly score. Fully explainable; no training.

## ML challenger (stretch, feature-flagged)
- Model: gradient-boosted trees (LightGBM/sklearn HistGradientBoosting), binary label "overload within next 10s".
- Training data: generated by running the scenario library (loadgen, varied seeds, isolation OFF to see raw overloads and ON for mitigated cases) → export per-second feature rows. Split **by scenario/seed**, not by row, to avoid leakage.
- Evaluate: precision/recall, PR-AUC, and — most important — **lead time**: seconds between first alert and actual victim degradation.
- Explainability: feature importances / SHAP-lite top factors surfaced as `top_factor`.

## Comparison (judge visual)
Chart: baseline vs ML alert time against ground-truth overload onset across N held-out scenarios; table of lead time, false alarms/hour.

## Failure handling
Timeout 150 ms → detector uses cached last prediction; sidecar down → in-process Go EWMA fallback. Predictions never *block* the hot path.

## Honest limits
Trained on simulated data; shows method, not production accuracy. Documented in the FAQ.
